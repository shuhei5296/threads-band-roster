# 未返信自動救済 v54 配備待ち

進行中のフェーズCへ影響させないため、Edge FunctionとDBへの本番反映は保留しています。

実装済みの判定方針：

- 自動救済は、本人照合済み・送信承認済み・未試行・未送信・定型文・最新名簿整合の候補だけ。
- 数値ID未確認かつ管理者確認記録なし、未登録、waiting_approval、failed、dead、processing、社長本人の古い重複は自動送信しない。
- 通常フェーズB/Cの送信枠と救済枠を分離する。
- 既存 `bot_legacy_reply_approvals`、原子的ジョブ確保、outbound履歴、監査ログを再利用する。

フェーズC終了後に必要な本番工程：

1. 終了監査と停止状態確認。
2. Edge Functionへ判定ポリシーと全区分レスポンスを統合。
3. 救済専用の件数・時間・利用率上限をDB側で原子的に管理する最小Migrationを適用。
4. v54を停止状態で配備。
5. 非送信確認後、本人確認・送信承認済み1件だけの限定試験を別途開始。
